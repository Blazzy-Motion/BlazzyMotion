# Demo version metadata

The Demo reads its component versions from assembly metadata generated by its project file. The values come from the same `BlazzyCoreVersion`, `BlazzyCarouselVersion`, `BlazzyBentoVersion`, `BlazzyGalleryVersion` and `BlazzyMarqueeVersion` MSBuild properties used by the library projects in `Directory.Build.props`.

Do not duplicate package numbers in `Services/AppVersions.cs`. Changing the central properties and rebuilding updates documentation badges, the component directory and displayed/copied installation commands. Explicit MSBuild version overrides are also reflected in the Demo build. Prereleases receive a preview badge; stable versions retain a stable badge.

These labels describe the code built into the Demo. They do not claim that a prepared version is already published on NuGet, and page rendering does not depend on NuGet network requests. Coordinate publication with deployment before advertising an unpublished release.

This change does not modify package versions, component library APIs or publication/deployment workflows. An automated production rebuild after successful package publication requires a separate approved workflow change.
